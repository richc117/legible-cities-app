# ADR-029: The assistant's configuration is committed

- **Status:** Accepted
- **Date:** 2026-09-09
- **Supersedes:** ADR-025
- **Superseded by:** none

## Context

ADR-025, taken on 2026-09-07, moved `CLAUDE.md`, `.claude/` and
`bin/test-hooks` out of this repository and into the maintainer's private
planning repository, which the checkout then reached through two gitignored
symbolic links. The reasoning was not that anything in them was sensitive.
The charter had committed them on the reasoning of ADR-014 and ADR-015 -
technical content, a reproducible checkout, hooks exercised in CI - and on
reviewing the public mirror the maintainer simply preferred them private.

Two days of working under that arrangement made its costs visible, and a
review of the private repository made its benefit measurable at zero.

**The cost.** The files are read constantly and edited in another repository,
so every change to a rule is a commit somewhere else. The hook tests stopped
running: `bin/test-hooks` exercises the two hooks that decide whether a
command may run at all, and neither the pre-commit configuration nor the
`preflight` workflow could invoke a script that had left the tree. Forty-seven
assertions about the only executable code here that makes a security decision
went unrun for two days. A fresh clone is also not reproducible: it has no
rules, no hooks and no skills until someone knows to make two symbolic links.

**The benefit.** A scan of the twenty-four files found nothing that must not
be public. No machine paths, no addresses, no keys, no session links. The
permission file is a list of read-only shell commands. The rules are the
project's own traps, written for whoever reads the code next. The skills are
Spec Kit's, regenerated by `specify init`. The one thing that looks alarming
is a deliberately split fake AWS key inside the scanner's own test, written
that way so the scanner it tests does not match it.

So the arrangement cost a working safety net and a reproducible checkout, and
bought privacy for content that did not need any.

## Options

**(a) Leave it.** No work. Keeps the hook tests unrunnable, keeps a fresh
clone incomplete, and keeps every rule change in another repository.

**(b) Bring it back, as it was before ADR-025.** Restores the tests, the
reproducible checkout and single-repository editing. Costs the privacy that
ADR-025 wanted, which this record argues was not buying anything.

**(c) Bring back only `bin/test-hooks` and the hooks, keep the rest private.**
Restores the tests at the smallest cost. Rejected as the worst of both: the
hooks are meaningless without the rules and the permission file they enforce,
and a reader would find tests for a configuration they cannot see.

## Decision

`CLAUDE.md`, `.claude/` and `bin/test-hooks` are committed to this repository
again. `bin/test-hooks` runs from the pre-commit hooks when a hook or the
script itself changes, and on every pull request in the `preflight` workflow.
Only what is personal to one machine stays out: `CLAUDE.local.md` for private
notes, and `.claude/settings.local.json` for per-machine permission
overrides. Both are gitignored.

## Consequences

**The hooks are tested again**, by the same run that scans for leaks. That is
the concrete thing this buys, and it is the reason to take the decision now
rather than at some tidier moment.

**A clone is complete.** Anyone who clones this repository gets the rules the
code was written under, the hooks that enforce them, and the tests that prove
the hooks work. That was ADR-014's and ADR-015's argument and it still holds.

**What the assistant is told is now public.** That is the honest cost. Anyone
can read the permission allowlist and see which commands run without asking,
and can read the rules to learn where this project's traps are. Neither is a
secret worth keeping: the allowlist is read-only commands, and the traps are
documented in the public architecture notes anyway.

**The history is not rewritten.** ADR-025's `git filter-repo` removed these
files from the history on both remotes, and GitHub still holds the pre-rewrite
commits behind pull-request refs. Bringing the files back does not undo that
and does not need to; the old copies are simply older versions of files that
are public again.

**Anything genuinely private must not drift into these files.** They are
public now, and `bin/preflight` scans them like everything else, which is the
protection that was missing while they lived outside the repository.
