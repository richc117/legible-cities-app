# Getting help

## Something went wrong

1. Read [Troubleshooting](docs/install.md#troubleshooting) in the install
   guide. It covers the messages people meet most: macOS saying the app is
   damaged, the app saying a bundled tool could not run, an antivirus taking
   a tool away, a feed that will not download, and the engine being
   unavailable. It also says where the logs are.
2. If it is not there, or the fix does not hold, open a
   [bug report](https://github.com/richc117/legible-cities-app/issues/new?template=bug.yml).
   In the app, open Settings and press **Copy diagnostics** under **Logs and
   diagnostics**, and paste what it copies. Read it first, and remove
   anything you would rather not share. The install guide's
   [Report a problem](docs/install.md#report-a-problem) has the steps.

Ideas and questions go in the same place, as an issue. GitHub Discussions are
off on purpose: the project keeps one board, and one maintainer cannot watch a
second place.

## A security problem

Do not open a public issue. [`SECURITY.md`](SECURITY.md) says how to report it
privately.

## What is supported

Only the latest release, the one the Releases page marks Latest, never a
release candidate. The app does not update itself, so a fix reaches you when
you install the new version over the old one. [`SECURITY.md`](SECURITY.md)
says the same under "Supported versions".

## No GitHub account

A report that cannot be filed as an issue because you have no account can go
to the maintainer by the contact route that
[`SECURITY.md`](SECURITY.md#reporting-a-vulnerability) publishes for anyone
not using GitHub's private reporting. Say at the start that it is a problem
report and not a security one. The maintainer opens an issue from it, with
your consent, so that it has a place on the board. That route and an issue are the only two:
there is no other mailbox, chat or forum.
